## 7. 匯入本系統的對應建議

| 原始資料 | 本系統 | 建議 |
|---|---|---|
| `branches[]` | `stores` | 一家分店一筆；`branch_id` 可作為店家代碼或外部識別碼保存 |
| 分店 | `warehouses` | 每店至少一個倉庫（建立店家時會自動建立預設倉） |
| `menu[].category` | 菜單分類 | 每店一份菜單，類別照原始資料 |
| `size: 小／大` | 菜單品項 | 兩種做法擇一：①拆成兩個品項（例「大腸麵線（小）」「大腸麵線（大）」，價格各自獨立，最直接）；②一個品項＋「份量」單選選項組，大份以加價表示。目前大小份價格多為 null，建議先用①避免加價金額需要推算 |
| `price: null` | 品項價格 | 不要匯成 0 元。測試時可給明顯的佔位價，並在品項備註寫「價格未核實」 |
| `combos[]` | 菜單品項 | 以一般品項建立（類別可設「套餐」）；如需扣庫，在連結商品分別設定組成品項 |
| `availability_notes` | 不建立該品項 | 精誠店不建立肉圓 |
| 外送平台 `sources` | 外送平台設定 | URL 末段是平台頁面識別碼，**不保證等於 API 用的 Store ID／Vendor Code**，正式串接須以平台後台提供的值為準 |
| `price_observations`／`price_conflicts` | 不匯入 | 只作為測試「平台價與門市價不同」情境的對照資料 |

## 8. 可用的測試情境

| # | 情境 | 用到的資料 | 驗證重點 |
|---|---|---|---|
| 1 | 價格未知的品項 | 精誠店、健行店全部品項 | 匯入或建立品項時，價格空值不會被靜默存成 0 |
